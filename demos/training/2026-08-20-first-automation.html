Facilitator notes
  • Open on the stats row: "everything you'll paste today is on this page — this link is yours to keep."

STEP 1

Pick your candidate

3 min

From last week's ranked backlog, take your #1 low-risk candidate.

Good picks are frequent, repeatable, and survivable if the output is wrong — because a person reviews it anyway. If your #1 feels big, shrink it to its smallest repeatable piece.

Before moving on, you have

One candidate, one sentence: "Every ___ I take ___ and produce ___."

Facilitator notes
  • Have 1–2 people say theirs out loud — it calibrates the room's scope.
  • Trip-up: candidates that need a connector nobody has set up. Fine for today — a file export or open browser page works as input.
STEP 2

Write the workflow card

6 min · 4 you-do

The card is the contract for the skill and its test. You are not building yet.

You do — 4 min

Open Claude Code in a folder with only the scrubbed material you need. Paste:

Use Plan Mode. Turn this automation candidate into the smallest useful skill.

Candidate: [paste one item from your top three]
Inputs: [files, connector, or browser page]
Output: [what I want back]

Read only. Do not send, publish, delete, edit, move, create, or change permissions.
Stop if information is missing, unclear, or sensitive.

Give me: trigger, inputs, output, human review, stop rule, and frozen safe test.
Do not build it yet.
What you get back

A short card: trigger, inputs, output, the human-review point, one stop rule, and a frozen safe test sample. Keep it — every later step refers to it.

Facilitator notes
  • Talking point: "frozen sample" means the same input every time — that's what makes before/after comparison honest.
  • Trip-up: people skip the stop rule. It's the line between an assistant and a liability.
  • Transition cue: when most screens show a card, ask one person to read their stop rule aloud.
STEP 3

Build it — baseline first

8 min · 5 you-do

Two build paths. Both require the same proof: a no-skill baseline before the skill exists.

If you have…Use this path
The shared Claude Skill FactoryUse it for the fuller test loop. Open it and say help me build a skill, then give it the card and sample.
Claude's Skill CreatorUse it if it's already in your Claude workspace. Same workflow card, same proof required below.
You do — 5 min 
I want to build a reusable Claude skill from this workflow card.

Workflow card:
[paste the card]

Use only this scrubbed sample: [file, connector scope, or exact browser page].
First create a no-skill baseline. Then build the skill and run it on the same
frozen sample. Read only; do not change anything. Stop rather than guessing.

Save the baseline, skilled result, and short comparison. Return a draft or local
artifact only; a person reviews it before anything happens.

For inputs, name the exact Asana project, Gmail search, Drive folder, or connector scope; attach a scrubbed transcript, report, or export; or inspect an exact open browser page without clicking anything that changes state.

A browser-only pilot is fine for learning. It cannot become a Cloud routine until its inputs are reachable through an approved connector, repository, or API.

Facilitator notes
  • Talking point: the baseline is captured before the skill exists — nobody grades on a curve.
  • While people build, narrate the next slide's worked example so slower builders don't feel stuck.

STEP 4

Prove it earns its place

5 min · 3 you-do

A fresh session — or a second model — judges the comparison. Not you, and not the session that built it.

You do — 3 min

Start a fresh Claude Code session, or ask a second model:

Read this workflow card, the no-skill baseline, and the skilled result from the same frozen sample.

Check accuracy, format, allowed inputs, unsupported claims, stop rules, and whether
the skilled result is clearly better or more consistent. List what still needs judgment.

Do not change either output. Give a short keep / revise / stop verdict with evidence.
What you get back

A keep / revise / stop verdict with evidence. Make one correction and rerun the same sample. If it still needs heavy steering, shrink the job.

Facilitator notes
  • Talking point: "the builder session is attached to its own work — that's why the reviewer is fresh."
  • Trip-up: people iterate five times live. One correction, one rerun. More is homework.
STEP 5

Graduate it — only when proven

3 min

A Cloud routine is a graduation, never a first experiment.

Cloud routines run on Anthropic-managed infrastructure, so keep them narrow:

RuleWhy
Skill committed to the included repositoryPersonal local skills are unavailable to Cloud routines.
Minimum connectors onlyEach connector is standing access the routine holds forever.
Draft or review artifact onlyNever a send, task change, or final decision.
Cloud, not Local — and Run now once before schedulingOne supervised run before any schedule exists.

When it's ready:

This skill has passed its frozen-sample test. Help me prepare it for a Claude Code
Cloud routine. Confirm the skill is committed in the selected repository, list the
minimum connectors and permissions needed, and write a routine prompt that produces
only a reviewable draft. Do not schedule it yet. I want to run it once first.
Facilitator notes
  • This step is a preview, not today's exercise — nobody schedules anything today.
  • Trip-up: browser-pilot skills can't graduate until inputs are connector/repo/API-reachable (from step 3).
DONE

Your definition of done

2 min
A workflow card and a frozen, scrubbed sample
A no-skill baseline and a skilled result on that same sample
A review verdict — keep, revise, or stop — from a fresh session
One stop rule and a named human-review point

The routine is a next step, not today's requirement. Homework: finish the proof loop on your candidate if you didn't get through it live, and bring the verdict next week.
